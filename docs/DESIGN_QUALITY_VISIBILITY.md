# 写作质量可视化方案

> 日期：2026-06-02
> 范围：编辑器质量徽章 + 全书质量趋势面板
> 依赖：`lib/evals/novelQuality.ts`（已有，零 token 纯启发式）

---

## 现状

`evaluateNovelQuality` 是一个成熟的 7 维评分函数（零 token，纯规则/统计），但只在后台自动生成引擎里调用。手动编辑的用户完全看不到质量数据。

## 目标

把质量数据从"隐形"变成"可见"，分两步走。

---

## 一、编辑器质量徽章（P0 / 低投入）

### 功能

EditorToolbar 右上角加一个徽章，显示当前章节所在滑窗的 7 维评分。点击弹出简版 breakdown。

### 交互

```
┌─ EditorToolbar ──────────────────────────────────┐
│  第 12 章 · 外宗来使          [92% 质量]  ▼      │
└──────────────────────────────────────────────────┘
        点击 ▼
┌──────────────────────┐
│  第 10-12 章滑窗评分  │
│                      │
│  情节推进  ████████░  9/10
│  连贯性    ████████░  8/10
│  逻辑      █████████  9/10
│  AI腔      ████████░  8/10
│  世界观    ███████░░  7/10
│  角色一致  █████████  9/10
│  文笔      █████████  10/10
│                      │
│  综合 85.7%           │
└──────────────────────┘
```

**触发时机**：
- 用户点击徽章 → 调 API 实时计算
- 自动生成模式下，生成完一章后自动更新（已有）

**冷启动**：少于 3 章时徽章灰色 + 提示"需要至少 3 章才能评估"。

### 技术方案

**新增 API**：`GET /api/novels/:id/quality?chapter=N`

```typescript
// 返回当前章所在滑窗（N-2, N-1, N）的评分
{
  window: [10, 11, 12],
  score: 85.7,
  dimensions: {
    plot_progress: { score: 9, max: 10 },
    continuity: { score: 8, max: 10 },
    // ...
  },
  level: "good" // critical | warning | good | excellent
}
```

API 内部逻辑：
1. 查 DB 取最近 3 个有内容的章节（含当前章）
2. 调 `evaluateNovelQuality({ bible, chapters })` 
3. 返回简化结果

**前端改动**：
- `EditorToolbar.tsx`：加徽章按钮 + 评分下拉 popover
- 新增 `useChapterQuality(novelId, chapterIndex)` hook：调 API + 管理 loading/error/cache
- 评分不超过 3 章时展示"冷启动"状态

**不改动**：`evaluateNovelQuality` 本身、自动生成引擎、数据库 schema。

**估时**：1.5h。

## 二、全书质量趋势面板（P1 / 中投入）

### 功能

在 `/novels/[id]` 详情页加一个"写作质量"tab 或 section，展示全书的 7 维评分趋势折线图。

### 界面

```
┌─ 写作质量 · 逆魂纪 ──────────────────────────────┐
│                                                    │
│  综合评分趋势                                       │
│  100% ┤                     ╭───                   │
│   90% ┤    ╭──╮  ╭──╮  ╭──╯                      │
│   80% ┤ ╭─╯  ╰──╯  ╰──╯                          │
│   70% ┤                                           │
│       └──┬──┬──┬──┬──┬──┬──┬──┬──┬──             │
│         1  5  10 15 20 25 30 35 40                │
│                                                    │
│  维度明细                                           │
│  ┌─ 情节推进 ────────────────────────────────┐    │
│  │ ████████████████████████████████████████   │    │
│  │ avg 9.6/10  峰值 ch5=10  谷值 ch1=6       │    │
│  └──────────────────────────────────────────┘    │
│  ┌─ AI腔 ──────────────────────────────────┐    │
│  │ ████████████████████████████████████████   │    │
│  │ avg 8.2/10  峰值 ch32=10  谷值 ch8=6     │    │
│  └──────────────────────────────────────────┘    │
│  ...（其余 5 维度同理）                            │
│                                                    │
│  风险标记                                           │
│  ⚠ ch7-9：AI腔连续 3 章低于 7 分                   │
│  ⚠ ch22：逻辑分骤降（9→4），可能情节矛盾            │
│  ✅ 全 40 章连贯性稳定在 8.0，零衰减                 │
└────────────────────────────────────────────────────┘
```

### 技术方案

**数据来源**：自动生成时 `quality.json` 落盘每章评分；手动编辑时按需调 API 计算并缓存。

**趋势图**：纯 CSS/SVG 折线图（零依赖），或者用 `recharts`（项目已有？检查一下）。横轴是章号，纵轴是分数，7 条线一图或分维度各一图。

**风险标记**：启发式规则——连续 3 章某维度低于阈值、相邻两章分数骤降 >30%、整体趋势是否下降。

**新增 API**：`GET /api/novels/:id/quality/trend`

返回：
```typescript
{
  chapters: [
    {
      chapterIndex: 1,
      title: "雨夜火房",
      score: 82.9,
      dimensions: { ... },
      evaluatedAt: "2026-05-31T10:00:00Z"
    },
    // ...
  ],
  summary: {
    overallAvg: 91.3,
    bestChapter: { index: 5, score: 95.7 },
    worstChapter: { index: 1, score: 82.9 },
    trend: "stable", // improving | stable | declining
    dimensionAvgs: { plot_progress: 9.6, continuity: 8.0, ... },
    riskFlags: [
      { chapters: [7,8,9], dimension: "ai_voice", avg: 6.3, message: "AI腔连续偏低" }
    ]
  }
}
```

**前端改动**：
- 新增 `/novels/[id]/quality` 页面
- NovelShell 加"写作质量"tab
- 纯 CSS/SVG 趋势图组件（或 recharts 如果已有）

**估时**：3h。
